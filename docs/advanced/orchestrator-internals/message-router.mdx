# MessageRouter

`MessageRouter` owns a background `ChannelHandler` that reads agent `STATUS` messages from the orchestrator's process-backed `MessageChannel` and emits corresponding callbacks through an `EventManager`.

## Current mapping

| `ServiceMessage.payload["event"]` | Emitted event | Callback data |
|---|---|---|
| `agent_started` | `OrchestratorEvent.AGENT_STARTED` | `agent_name` |
| `agent_ready` | `OrchestratorEvent.AGENT_READY` | `agent_name` |
| `agent_close` | `OrchestratorEvent.AGENT_TERMINATED` | `agent_name` |
| `agent_heartbeat` | `OrchestratorEvent.AGENT_HEARTBEAT` | `agent_name` |
| `ERROR` | `OrchestratorEvent.AGENT_ERROR` | `agent_name`, `error_message` |

Messages whose top-level type is not `STATUS`, and unknown event values, are logged and ignored.

## Construction and lifecycle

The orchestrator constructs and starts the router automatically:

```python
self.message_router = MessageRouter(
    self.event_bus.event_manager,
    self.msg_channel,
    self.logger,
)
self.message_router.start()
```

The relevant methods are:

```python
router.start()
router.is_running()
router.stop(timeout=2.0)
```

`stop()` signals the internal `ChannelHandler`, waits up to the supplied timeout, then drops the handler reference. The implementation does not promise that every queued message will be processed before return.

## Stale-heartbeat filtering

On `agent_close`, the router records the sender in a thread-safe terminated-agent set. Later heartbeats from that name are ignored:

```python
router.mark_agent_terminated("worker")
router.is_agent_terminated("worker")       # True
router.reset_termination_state("worker")
router.get_terminated_agents()             # returns a copy
```

Only stale heartbeats are filtered. Other supported messages from a name already marked terminated still follow their normal mapping.

## Event-history limitation

The constructor accepts an `EventManager`, and `Orchestrator` passes `event_bus.event_manager`. The router therefore triggers registered callbacks directly rather than calling `OrchestratorEventBus.emit()`.

<Warning>
Agent lifecycle events routed here are not automatically recorded in `EventStore` in the current implementation. Do not treat CLI `history` as a complete lifecycle audit log.
</Warning>

## Message shape

Agents normally create messages with:

```python
from PyOrchestrate.core.utilities.messaging import ServiceMessage

message = ServiceMessage.create_status(
    sender="worker",
    status="ready",
    event_name="agent_ready",
)
```

The router reads `msg.type`, `msg.sender`, and the `event` and optional `message`/`error` keys in `msg.payload`.
