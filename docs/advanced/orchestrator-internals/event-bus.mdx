# OrchestratorEventBus

`OrchestratorEventBus` combines two components:

- `EventManager`, which dispatches callbacks asynchronously;
- `EventStore`, which keeps bounded event history.

Calling `OrchestratorEventBus.emit()` performs both operations. Direct calls to
the underlying `EventManager` dispatch callbacks without writing history.

## Register Callbacks

Application code can use the high-level orchestrator method:

```python
from PyOrchestrate.core.utilities.event import OrchestratorEvent


def on_agent_started(agent_name, event_time=None, **kwargs):
    print(f"{agent_name} started at {event_time}")


orchestrator.register_event(
    OrchestratorEvent.AGENT_STARTED,
    on_agent_started,
)
```

Equivalent low-level registration:

```python
orchestrator.event_bus.register_callback(
    OrchestratorEvent.AGENT_STARTED,
    on_agent_started,
)
```

Callbacks run in an `EventManager` thread pool. Parameters are filtered against
the callback signature, and `event_date`/`event_time` are added when the
callback accepts them.

## Emit and Record an Event

```python
orchestrator.event_bus.emit(
    OrchestratorEvent.AGENT_STARTED,
    agent_name="worker-1",
)
```

The event is dispatched to callbacks and stored with the enum **value** as its
name. For example:

| Enum member | Stored `event_name` |
|---|---|
| `OrchestratorEvent.AGENT_STARTED` | `agent_started` |
| `OrchestratorEvent.AGENT_READY` | `agent_ready` |
| `OrchestratorEvent.AGENT_TERMINATED` | `agent_terminated` |
| `OrchestratorEvent.AGENT_ERROR` | `agent_error` |
| `OrchestratorEvent.AGENT_HEARTBEAT` | `agent_heartbeat` |

Use these lowercase values when filtering event history.

## Query History

Use the event-bus helpers:

```python
recent = orchestrator.event_bus.get_history(limit=50)
worker_events = orchestrator.event_bus.get_history(
    agent_name="worker-1",
    limit=20,
)
errors = orchestrator.event_bus.get_history(
    event_type="agent_error",
    limit=10,
)
```

Or use `EventStore.last()` directly when `after_seq` is required:

```python
events = orchestrator.event_bus.event_store.last(
    n=50,
    agent="worker-1",
    event_name="agent_ready",
    after_seq=100,
)
```

`EventStore` exposes `last()`, `latest()`, `latest_all_agents()`, `stats()`, and
`get_capacity_info()`. It does not expose a `query()` method.

## Current Lifecycle-History Limitation

The current `Orchestrator` gives `MessageRouter` the underlying
`EventManager`, not the complete `OrchestratorEventBus`. Agent lifecycle
messages therefore trigger registered callbacks but bypass automatic history
recording.

Consequences in the current release:

- `register_agent()` is recorded because it calls `event_bus.emit()` directly;
- messages such as agent started, ready, terminated, error, and heartbeat reach
  callbacks but are not automatically stored by `MessageRouter`;
- `history` can contain orchestrator records such as `INIT`, explicit event-bus
  emissions, and command-interface error records;
- a lifecycle filter may return no records even though the callback ran.

This is a runtime limitation, not a CLI filter issue. Do not rely on lifecycle
history for auditing until the router is connected to `OrchestratorEventBus`.

## CLI History

Read recent stored records:

```bash
pyorchestrate history --last 20
pyorchestrate history --agent worker-1
pyorchestrate history --type agent_error
pyorchestrate history --after-seq 100
```

Successful JSON records contain:

```text
seq
timestamp
t_wall
t_mono_ns
category
event_name
agent
severity
data
```

## EventStore Configuration

The orchestrator creates its event store from these configuration fields:

```python
config = Orchestrator.Config(
    history_max_events=1000,
    history_payload_bytes=512,
)
```

`history_max_events` controls the default ring-buffer capacity.
`history_payload_bytes` limits each stored payload value.

The default orchestrator store also uses a per-agent policy for heartbeats:

```python
from PyOrchestrate.core.orchestrator.event_store import (
    BucketRingStore,
    EventStore,
)

store = EventStore(
    capacity=1000,
    event_policies={
        "agent_heartbeat": BucketRingStore(per_agent_capacity=2),
    },
)
```

`BucketRingStore` is defined in
`PyOrchestrate.core.orchestrator.event_store`; it is not re-exported from
`PyOrchestrate.core.orchestrator`.

There is currently no `Orchestrator` constructor parameter for a custom event
store. Replacing `orchestrator.event_bus.event_store` after construction is not
equivalent, because `CommandInterface` retains the original store reference.

## Custom Store Policies

A custom policy must implement the `StorePolicy` interface:

```python
class StorePolicy:
    def append(self, event):
        ...

    def last(
        self,
        n=100,
        *,
        agent=None,
        event_name=None,
        after_seq=None,
    ):
        ...

    def stats(self, *, agent=None):
        ...

    def capacity_info(self):
        ...
```

Policies are selected by the exact stored `event_name`.

## Thread Safety

- `EventManager` protects lazy thread-pool initialization.
- `EventStore` serializes reads and writes with a lock.
- Callback failures are logged without stopping other callbacks.

Shut down callback execution explicitly when using the event bus outside the
normal orchestrator lifecycle:

```python
orchestrator.event_bus.shutdown()
```
