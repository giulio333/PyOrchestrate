# Event Manager

`EventManager` maps enum members to callbacks and executes those callbacks asynchronously in a thread pool. Application code normally registers orchestrator callbacks through `orchestrator.register_event(...)` or `orchestrator.event_bus.register_callback(...)`.

## Register callbacks

```python
from PyOrchestrate.core.utilities.event import OrchestratorEvent

def on_ready(agent_name, event_time):
    print(f"{agent_name} ready at {event_time}")

orchestrator.register_event(OrchestratorEvent.AGENT_READY, on_ready)
```

The supported orchestrator events are:

| Event | Callback data emitted by the current source |
|---|---|
| `AGENT_REGISTERED` | `agent_name` |
| `AGENT_STARTED` | `agent_name` |
| `AGENT_READY` | `agent_name` |
| `AGENT_TERMINATED` | `agent_name` |
| `AGENT_ERROR` | `agent_name`, `error_message` |
| `AGENT_HEARTBEAT` | `agent_name` when routed by `MessageRouter` |

`event_date` and `event_time` are added by `EventManager` when a callback accepts them or accepts `**kwargs`.

## Callback semantics

- callbacks run asynchronously in a lazily created `ThreadPoolExecutor`;
- the default maximum is 10 callback workers;
- keyword arguments are filtered to the callback signature unless it accepts `**kwargs`;
- callback exceptions are logged and isolated from the remaining listeners;
- callbacks for the same event are submitted in registration order, but completion order is not guaranteed.

## Direct use

```python
from enum import Enum
from PyOrchestrate.core.utilities.event_manager import EventManager

class TaskEvent(Enum):
    COMPLETED = "completed"

manager = EventManager(max_workers=4)
manager.register_event(TaskEvent.COMPLETED, lambda result: print(result))
manager.emit(TaskEvent.COMPLETED, result="ok")
manager.shutdown()
```

`shutdown(wait=True)` waits for submitted callbacks by default. After shutdown, new emissions are ignored.

For an orchestrator-owned manager, prefer:

```python
orchestrator.event_bus.shutdown()
```

There is no `orchestrator.event_manager` public attribute.

## History is a separate layer

`EventManager` only dispatches callbacks. `OrchestratorEventBus` adds an `EventStore` and records events passed through `event_bus.emit(...)`. See [Event Bus](/advanced/orchestrator-internals/event-bus) for the current lifecycle-history limitation.
