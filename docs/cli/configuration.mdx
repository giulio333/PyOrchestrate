# CLI Configuration

Runtime CLI commands communicate with the orchestrator through a ZeroMQ ROUTER/DEALER channel over TCP. The relevant settings live in `Orchestrator.Config`.

## Basic Configuration

```python
from PyOrchestrate.core.orchestrator import Orchestrator, RunMode

config = Orchestrator.Config(
    enable_command_interface=True,
    command_zmq_address="tcp://127.0.0.1:5555",
    run_mode=RunMode.DAEMON,
)

orchestrator = Orchestrator(config=config)
```

`RunMode.DAEMON` is useful for an orchestrator that must remain available for runtime commands even when no agents are running.

## Command Interface Options

| Option | Type | Default | Description |
|---|---|---|---|
| `enable_command_interface` | `bool` | `True` | Enable the external command interface |
| `command_zmq_address` | `str` | `"tcp://127.0.0.1:5555"` | Address on which the orchestrator binds its ZeroMQ ROUTER socket. Loopback by default, so only this machine reaches it |
| `allowed_commands` | `set[str]`, preset `str`, or `None` | `None` | Restrict accepted commands; `None` allows every command |
| `run_mode` | `RunMode` | `RunMode.STOP_ON_EMPTY` | Decide whether the orchestrator exits when no work remains |
| `history_max_events` | `int` | `5000` | Event history capacity |
| `history_payload_bytes` | `int` | `256` | Maximum stored payload size for each event |

The CLI client connects to `tcp://127.0.0.1:5555` by default. Its `--socket` option accepts a ZeroMQ address:

```bash
pyorchestrate status --socket tcp://127.0.0.1:5555
```

## Bind and Connect Addresses

The default binds the loopback interface, which is what local CLI and web
clients connect to. Nothing outside the machine can reach it:

```python
config = Orchestrator.Config(
    command_zmq_address="tcp://127.0.0.1:5555",
)
```

For access through another network interface:

```python
config = Orchestrator.Config(
    command_zmq_address="tcp://*:5555",
)
```

Clients must replace the wildcard with an address they can reach:

```bash
pyorchestrate status --socket tcp://192.0.2.10:5555
```

<Warning title="No transport authentication">
The command interface does not add authentication or encryption to ZeroMQ. Any client that reaches the port can run every command in `allowed_commands` — `shutdown`, `stop` and `start` included — and read the agent configurations `ps` returns. Do not expose it to an untrusted network: prefer the default loopback binding, and back a wider one with firewall rules, a private network and restrictive command permissions. The orchestrator logs a warning at startup whenever the address it binds is reachable from other hosts.
</Warning>

## Command Permissions

`allowed_commands=None` enables every registered command. You can instead use a predefined preset:

| Preset | Intended use |
|---|---|
| `"production"` | Read-only operational commands, including dependencies and history |
| `"development"` | Every command |
| `"read_only"` | Read-only inspection commands |
| `"monitoring"` | Status, statistics, history, and command inspection |

```python
config = Orchestrator.Config(
    command_zmq_address="tcp://127.0.0.1:5555",
    allowed_commands="monitoring",
)
```

Or provide an explicit set:

```python
config = Orchestrator.Config(
    command_zmq_address="tcp://127.0.0.1:5555",
    allowed_commands={"ps", "status", "commands"},
)
```

The available command names are:

```text
commands
dependencies
history
history-stats
ps
shutdown
start
stats
status
stop
```

Unknown names in a custom set are ignored. Passing a list is invalid; use a `set`.

Inspect the effective permissions at runtime:

```bash
pyorchestrate commands
```

## Long-Running Orchestrators

`RunMode.STOP_ON_EMPTY` exits when all registered work is complete. For a service controlled through the CLI, use `RunMode.DAEMON` and shut it down explicitly:

```python
from PyOrchestrate.core.orchestrator import Orchestrator, RunMode

config = Orchestrator.Config(
    enable_command_interface=True,
    command_zmq_address="tcp://127.0.0.1:5555",
    allowed_commands="development",
    run_mode=RunMode.DAEMON,
)

orchestrator = Orchestrator(config=config)
orchestrator.start()
orchestrator.join()
```

```bash
pyorchestrate shutdown
```

`join()` returns once the agents have been stopped and joined. Raise
`agent_stop_timeout` (default `10.0` seconds) when agents need longer to finish
the work in flight before shutdown escalates.

### Shutting Down From Code

The CLI is not the only way out of a `DAEMON` loop. `Orchestrator.stop()` also
ends it, so a signal handler or a supervising thread can bring the service down
without a command socket:

```python
import signal

signal.signal(signal.SIGTERM, lambda *_: orchestrator.stop())

orchestrator.start()
orchestrator.join()   # returns once stop() is called
```

`stop()` only *requests* termination. When there is no `join()` running to
follow it — an orchestrator embedded in something else, for instance — call
[`shutdown()`](/api/orchestrator) instead: it stops the agents, waits for them,
then releases everything the orchestrator owns, and returns the names of any
agents still alive.

```python
survivors = orchestrator.shutdown()
```

<Warning>
  Both are one-way. The worker pool stops accepting starts, so an orchestrator
  that has been stopped cannot be restarted — build a new one.
</Warning>

## Validation

Configuration is validated when the orchestrator is created. You can also inspect validation results directly:

```python
config = Orchestrator.Config(
    enable_command_interface=True,
    command_zmq_address="tcp://127.0.0.1:5555",
)

for result in config.validate():
    print(result.severity, result.field, result.message)
```

When the command interface is enabled, `command_zmq_address` must be a non-empty value.

## Containers

TCP-based ZeroMQ does not require a shared socket volume. The orchestrator and its client need network connectivity and matching ports.

For two containers on the same Compose network:

```yaml
services:
  orchestrator:
    build: .
    command: python orchestrator.py

  monitor:
    build: .
    command:
      - pyorchestrate-web
      - --host
      - 0.0.0.0
      - --socket
      - tcp://orchestrator:5555
```

The default `tcp://127.0.0.1:5555` is not reachable from another container, so this composition needs the orchestrator to bind `tcp://*:5555` explicitly. Keep port `5555` unpublished so it stays on the Docker network: publishing it to the host puts an unauthenticated control port on the host's interfaces.

## Troubleshooting

### Connection failure

Check the configured bind address and the client endpoint:

```bash
pyorchestrate status --socket tcp://127.0.0.1:5555
lsof -nP -iTCP:5555 -sTCP:LISTEN
```

### Command rejected

Inspect the effective permission set:

```bash
pyorchestrate commands
```

Then update `allowed_commands` if the operation should be permitted.

### Address already in use

Only one orchestrator can bind a given address and port. Select another port in both the orchestrator configuration and the client command.
