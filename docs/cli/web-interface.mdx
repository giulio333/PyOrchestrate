# PyOrchestrate Web Interface

The web interface is a read-only FastAPI layer for browser-based monitoring. It uses the same ZeroMQ command interface as the CLI and renders responses as HTML or JSON.

## Start the Server

```bash
pyorchestrate-web
```

Default settings:

| Option | Default | Description |
|---|---|---|
| `--host` | `127.0.0.1` | HTTP server bind host |
| `--port` | `8000` | HTTP server port |
| `--socket` | `tcp://127.0.0.1:5555` | Orchestrator ZeroMQ address |
| `--enable-auth` | disabled | Require bearer-token authentication |
| `--auth-token` | none | Token required when authentication is enabled |

The option is named `--socket` for compatibility, but it expects a ZeroMQ TCP address.

Connect to a custom orchestrator endpoint:

```bash
pyorchestrate-web \
  --host 127.0.0.1 \
  --port 8000 \
  --socket tcp://127.0.0.1:5555
```

Open `http://127.0.0.1:8000`.

## Authentication

Enable bearer-token authentication explicitly:

```bash
pyorchestrate-web \
  --enable-auth \
  --auth-token "replace-with-a-secret-token"
```

The token must be passed through `--auth-token`; the command does not currently read an authentication token from an environment variable automatically.

Authenticated JSON request:

```bash
curl \
  -H "Authorization: Bearer replace-with-a-secret-token" \
  -H "Accept: application/json" \
  http://127.0.0.1:8000/api/orchestrator/status
```

<Warning title="Use TLS for remote access">
Bearer tokens are not encrypted by HTTP. Keep the server on loopback or place it behind a trusted HTTPS reverse proxy before allowing remote access.
</Warning>

## Available Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/` | Redirect to the orchestrator status view |
| `GET` | `/api/health` | Check the web service itself |
| `GET` | `/api/orchestrator/status` | Read orchestrator status |
| `GET` | `/api/agents` | List registered agents |
| `GET` | `/api/agents/{agent_name}` | Read one agent's status |
| `GET` | `/api/orchestrator/dependencies` | Read agent dependencies |
| `GET` | `/api/orchestrator/stats` | Read agent and orchestrator statistics |
| `GET` | `/api/history` | Read event history |
| `GET` | `/api/history/stats` | Read aggregated event statistics |
| `GET` | `/docs` | Open the generated FastAPI API reference |

The interface does not expose agent start, stop, restart, or shutdown endpoints.

<Warning title="Current backend limitations">
`/api/agents/{agent_name}` and `/api/orchestrator/dependencies` delegate to the two runtime handlers that still read the removed `orchestrator.dependencies` attribute, so they can return an internal backend error. `/api/agents` and `/api/orchestrator/status` are unaffected.
</Warning>

## HTML and JSON

Browser requests render an HTML monitoring view. Request JSON with either `?format=json` or an `Accept` header:

```bash
curl "http://127.0.0.1:8000/api/agents?format=json"
```

```bash
curl \
  -H "Accept: application/json" \
  http://127.0.0.1:8000/api/history
```

## History Filters

The history contains stored events only. Agent lifecycle callbacks routed by `MessageRouter` currently bypass the store, so this endpoint is not a complete lifecycle audit log.

The history endpoint accepts:

| Query parameter | Description |
|---|---|
| `last` | Maximum number of recent events |
| `agent` | Filter by agent name |
| `event_type` | Filter by event name |
| `after_seq` | Return events after a sequence number |

```bash
curl \
  -H "Accept: application/json" \
  "http://127.0.0.1:8000/api/history?last=20&agent=Worker"
```

## Production Topology

Keep both internal services private when possible:

```text
Browser
   |
HTTPS reverse proxy
   |
pyorchestrate-web :8000
   |
ZeroMQ TCP :5555
   |
Orchestrator
```

Example:

```bash
pyorchestrate-web \
  --host 127.0.0.1 \
  --port 8000 \
  --socket tcp://127.0.0.1:5555 \
  --enable-auth \
  --auth-token "$AUTH_TOKEN"
```

Here the shell expands `AUTH_TOKEN`; `pyorchestrate-web` itself does not read the variable.

## Troubleshooting

### Web server is unavailable

Confirm the HTTP listener:

```bash
curl -f http://127.0.0.1:8000/api/health
lsof -nP -iTCP:8000 -sTCP:LISTEN
```

### Orchestrator data cannot be loaded

The health endpoint only checks the web service. Test the ZeroMQ endpoint separately:

```bash
pyorchestrate status --socket tcp://127.0.0.1:5555
```

Verify that the orchestrator command interface is enabled and bound to the expected address.

### Authentication fails

Pass the same token supplied at startup:

```bash
curl \
  -H "Authorization: Bearer replace-with-a-secret-token" \
  http://127.0.0.1:8000/api/health
```
